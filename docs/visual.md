# 見た目の判断

## 出発点(2026-10-22)

雛形(2026-10-16)のスタイルを見た本人の指摘(原文):

> 全体的に余白の使い方がキモい。グルーピングの原則を思い出して。色使いもかっこよくない。ぼんやりとしていて、インパクトに欠ける。もう少し色々試してみて。astraやsolにもみてもらって意見をもらって。最終的に3-6案くらいに絞って私に見せて

雛形の状態: 背景 #121212、本文 #e6e6e3、薄い文字 #8c8c88。節間が一律 7rem、節内が一律 1〜1.5rem で、まとまりが目で分からない。写真以外に色が無く、全体が中間調。

## 案の比較の仕組み

- `src/styles/variants/<name>.css` に1案1ファイル。すべてのセレクタを `html[data-v="<name>"]` で始める(Astro のスコープ付きスタイルより詳細度が高くなる)。
- 開発サーバーで `?v=<name>` を付けると `<html data-v="<name>">` が付き、その案で表示される。sessionStorage に残るのでページを移っても保たれる。`?v=` (空)で戻す。
- 案が決まったら global.css と各コンポーネントに畳み込み、`variants/` と切り替えの仕組みを消す。

## 候補(2026-10-22)

astra(Codex 相談役)の診断: 余白の量より「情報の階層と距離の対応」が弱い。英名・所属・節ラベル・年・要約・フッターがすべて薄い色に集約され、役割の違う情報が同じ階調になっている。期間欄 11rem で同じ項目の横の結び付きが弱い。短い導入を 7rem で独立した区画として扱いすぎ。astra は4方向(索引・展示台・台帳・操作色)を出し、索引を第一候補にした。sol(Codex 実装役)は sol-a(無彩色・左列ラベル)と sol-b(大きな名前と黄緑のアクセント)を書いた。

7案を描いて5案に絞った。落としたのは sol-a(tight と sheet の中間で、どちらかに吸収できる)と sol-b(display と同じ方向。アクセントを黄緑にしてラベルに使う点だけ違う)。

| 案 | 方向 | 出どころ | 余白(節間 : ラベル→内容) | 色 |
|---|---|---|---|---|
| tight | 索引。密度と整列で探せる道具にする | astra 案A | 4rem : 1rem | #101010 / #f2f2f2 / #aaaaaa |
| display | 大きな名前、2列の大きな写真、1色の操作色 | Claude(astra 案B+D と同方向) | 7rem : 1.25rem | #0a0a0a / #ffffff / #ff4d00 |
| ledger | 台帳。1列の横長項目で文字を主役に | astra 案C | 3rem : 0.75rem | #151515 / #eeeeee の2色 |
| sheet | 仕様書の2列。左に節名(sticky)、右に中身 | Claude | 3.5rem : 0(横並び) | #111111 / #ededea / #7d7d79 |
| paper | tight の余白で地色だけ明るく反転 | Claude | 5rem : 0.75rem | #f3f2ed / #161616 / #6f6f6a |

見るには開発サーバーで `/?v=tight` のように付ける(`&plain=1` で本番の見え方)。
