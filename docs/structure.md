# 構成の判断

## 前提(2026-10-16)

- スコープは本人確定の3点: 作品の追加・経歴の追加・全体の構成の刷新。
- 読み手が変わった。旧サイトはアルバイト応募用で、今回は就活(2028年卒)と外部へのアピール。採用担当が数分で「誰で・何ができて・何を作ったか」を掴めることを目的にする。
- design-system(`mf/design-system/worldview.md` の D3)はポートフォリオを「縛る」側に入れている。従うもの: ブランド層は無彩色で最大3色、書体は Intel One Mono と Noto Sans JP、文は言い切りで誇張形容詞を使わない。

## ページ

| URL | 中身 |
|---|---|
| `/` | 名前・所属・自己紹介の1〜2行 → 選抜作品(featured)→ 経歴 → 研究・発表 → 受賞 → 連絡先 |
| `/works/` | 全作品を年ごとに |
| `/works/<slug>/` | 1作品。メタ(年・文脈・担当・道具)→ 本文と画像・動画 → リンク |

旧サイトは home と works の2階層で、home の中身は一文だけだった。トップ1枚で経歴まで読み切れる形に変えたのは、就活の読み手が最初の1画面で判断するため。経歴を別ページに分けないのは、量が1画面に収まる見込みだから。

作品詳細にメタ欄(context・role)を足したのは、旧サイトに無かった「どの場で作り、自分が何を担ったか」が就活では必ず聞かれるため。共同制作(WISS2024・SNDC2026)は role を必ず書く。

## 定石との照合(2026-10-22)

ポートフォリオサイトの型は読み手で決まり、主に4つ: 2階層型(トップ1枚＋作品詳細。採用担当全般向け)、ケーススタディ型(作品ごとに課題→過程→結果の長文。UX・プロダクトデザイン職向け)、グリッド型(画像の格子のみ。作家・ビジュアル職向け)、学術ページ型(所属・関心・業績リスト・CV。研究職向け)。本サイトは2階層型。本人の確認(2026-10-22):

> 2階層型で良さそう

2階層型を取る根拠: 志望職種が未定で作品が研究・物理制作・ソフトウェア・コンペに横断しているため、軸が決まっている前提の他3型は取れない。2階層型は headline と featured の順を変えるだけで後からデザイン寄り・研究寄りに傾けられる。ケーススタディ型に寄せる場合も、選抜作品の本文を「なぜ作ったか・何をしたか・難所と解決・結果」の4段落にすれば済み、ページ構成は変わらない。グリッド型は実物写真が揃うまで成立しない。

作品一覧への導線は3か所で役割が違う: selected works の見出し右の「all works (件数) →」が主(2026-10-22 に本人がグリッド下から見出し右へ移すと決定。ヘッダーの左右配置と同じ文法で、グリッド下に行が増えない。件数は draft を除いた作品数をビルド時に出す)、ヘッダー nav の works は全ページ共通の現在地と移動用、作品ページ末尾の「← works」は読了後の戻り。フッターだけに置く・「もっと見る」で同じページに展開する形は取らない(別ページのほうが採用担当の流し読みと PDF 化に向く)。

## 選抜作品

トップに出すのは `featured` を持つ作品だけで、数字が小さい順。6件前後を想定。2026-10-16 時点の4件(キャンドルモビール・ワットチェッカー・モニタ壁掛けパーツ・40%キーボード)は、本人の選定までの仮置き。

## メディア

- 画像は作品フォルダに置き、Astro がビルド時に webp へ変換・縮小する(旧 jpg 400KB 前後 → カード用 6〜90KB)。
- 動画は `public/media/<slug>/`。**Cloudflare Pages は1ファイル25MiBが上限**で、旧動画は最大52MB(candle_mobile)あったため、全件を `scripts/encode-video.mjs` で再エンコードした(最大7.4MB)。元動画は旧サイトの `media/` に残っている。
- 旧サイトの `media/` 31ファイルは全件移した。作品一覧のタイル専用だった画像(各 `_001.jpg` など)はカバー画像(`cover`)になった。本文は旧サイトの記述を原文のまま移し、カード用の `summary` だけ新しく書いた。

## 公開まで決めること

- 公開先のサブドメイン(m-kw.net 配下ならドメイン費用は追加ゼロ。DNS が Cloudflare にあるので Cloudflare Pages が最短)。決まったら `astro.config.mjs` に `site` を入れる。
- 検索エンジンに出すか。決まるまで全ページ `noindex`(`profile.indexable`)。
- GitHub リンクを載せるか。2026-10-16 時点で morikawa976321 の公開リポジトリは0件で、リンク先は空のプロフィールになる。
